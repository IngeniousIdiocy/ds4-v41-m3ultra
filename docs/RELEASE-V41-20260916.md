# September 16 update: all validated post-launch decode gains

> **Latest update:** [September 16 decode consolidation](DECODE-CONSOLIDATION-20260916.md).
> The measurements and release identity below describe the earlier release stage.

This update brings the validated V4.1 UAT decode work into the public branch.
**All adopted kernel optimizations are on by default**, including the six
switches that were explicit opt-ins during UAT. DSpark still requires its
support weights and the existing `--dspark` serving setup; serial improvements
apply without DSpark. Each retained optimization keeps an off switch for
diagnosis and rollback.

## Performance since the original public release

Same M3 Ultra Mac and Q4 target weights; established fixture protocols.

| Decode workload | Original public release | Updated release configuration |
| --- | ---: | ---: |
| Serial, 8k context | 31.3 t/s | **33.3 t/s** |
| Serial, 300k context | 28.3 t/s | **31.7 t/s** |
| DSpark on code | 40.5 t/s | **46.4 t/s** |
| DSpark on agent turns, answer phase | 41.3 t/s | **50.0 t/s** |
| Six-row verifier block | 112 ms | **90.8 ms** |
| Normalized verifier weight traffic | 337 GB/s | **415 GB/s** |

The right column was measured in UAT with the adopted paths enabled. This
public integration preserves those paths, promotes their settings to defaults,
and removes rejected alternatives. It is not a newly timed release binary.
The release evidence records the UAT identity and the public integration checks.

The agent-answer metric uses the same common estimated answer-token numerator
divided by measured streaming answer-phase durations throughout. It is not the
rate over the whole reasoning-heavy turn. Reasoning remains serial by default.
The weight-traffic calculation also stays the same: 37.657 GB per verifier block
divided by block time, **not physical DRAM counter measurements**.

Prefill, TTFT, and disk-cache restoration were not retimed in this decode
campaign. Their original release measurements remain in the historical tables;
they are not new claims for this update. Whole-turn screenshots and the
[prompting experiment](PROMPTING-V41.md) are different workloads.

## What changed

| Area | Shipped change | Control |
| --- | --- | --- |
| Decode scheduling | Reorder independent Q8 pair and routed Q4 gate/up jobs for locality | `DS4_DS41_MTP_Q8_SWIZZLE=0`, `DS4_DS41_MTP_GU_SWIZZLE=0` |
| Long-context serial decode | Reuse query loads in the streamed index scorer, preserving ordered products | `DS4_DS41_INDEX_SCORE_STREAM=0` |
| Serial FFN | Fuse HC expansion into the routed FFN producer with the standalone path's ordered FP32 FMAs | `DS4_DS41_FFN_PRODUCER=0` |
| Serial query projection | Four independent output channels per cohort; same per-output reductions and HC completion protocol | `DS4_DS41_HC_STREAM_LAYOUT=0` (default `2`) |
| Q8 verification | Three-row weight reuse for output-B/shared-down; the query-B stream path remains selected | `DS4_DS41_MTP_Q8_TRIO_MASK=0` (default `80`) |
| Engram verification | Three-row F16 weight reuse with the original arithmetic | `DS4_DS41_MTP_F16_TRIO=0` |
| Routed experts | Stable expert-ID ordering for independent gate/up jobs | `DS4_DS41_MTP_GU_EXPERT_SORT=0` |
| Router selection | Exact SIMD batch top-six and hierarchical serial selection, with original tie/nonfinite fallbacks | `DS4_DS41_ROUTER_SIMD=0`, `DS4_DS41_ROUTER_HIER=0` |
| Markov correction | Memoize the exact existing correction vector in a 64-entry per-drafter FIFO | `DS4_DS41_MARKOV_CACHE=0` |
| Router projection | Batch independent F32 rows in one launch | `DS4_DS41_MTP_F32_ROWS=0` |
| RoPE/KV work | Batch independent verifier pointwise operations | `DS4_DS41_MTP_POINTWISE_BATCH=0` |
| Routed down projection | Wide loads and six-row scheduling in 256-output tiles, unchanged expert sum order | `DS4_DS41_MTP_DOWN_WIDE=0` |
| Expert job sorting | SIMD-register sort for the same stable independent-job ordering | `DS4_DS41_MTP_GU_SORT_SIMD=0` |
| Q8 stores | Fold the existing BF16 rounding into batch output stores; combine barriers across independent pair/trio reductions | `DS4_DS41_MTP_Q8_ROUND=0` |
| Shared SwiGLU stores | Fold the same BF16 rounding into the activation store | `DS4_DS41_MTP_SWIGLU_ROUND=0` |

Cross-row sharing already existed in the original release. The new work extends
it selectively and improves scheduling; it does not introduce MTP weight reuse
for the first time. The Markov change caches the existing CPU correction rather
than replacing it with a different Markov model or a GPU approximation.

### Admission controller

The cumulative update includes a bounded-loss change, not just kernels. Faster
serial steps moved break-even enough that a kernel-only candidate backed off
earlier on a code fixture and lost about 1.6%. That regression was retained in
the experiment record and addressed before adoption.

The controller now carries measured net loss across three-attempt windows until
unrepaid loss exceeds half a median serial step. Wins repay debt but never bank
credit. Backoff still uses the existing 16/32/64/128-token ladder. Debt resets on
backoff, evidence reset, and reasoning exit. Confidence floor 0.75, minimum
useful prefix three, six-row verification, serial reasoning, sampled-decode
correctness, and the session fault latch retain their roles.
`DS4_DS41_DSPARK_LOSS_BUDGET=0` restores immediate losing-window backoff.
The later material/answer50 kernel campaigns did not retune this policy.

## Rejected code is removed; the evidence remains

The public tree excludes the unsuccessful compact F16 Engram grid, split
collapse/RMS path, non-selected two/eight-channel specialized query layouts,
and unused specialized shared-expert layouts, including their switches and
dedicated tests. The original working kernels remain as rollback controls.
Most other rejected candidates never entered production code at all.

The [complete chronological research records](experiments/v41-20260915/README.md)
retain the failures: slower MMA and FP16 variants, changed-order fidelity
failures, microbenchmarks that did not transfer to model speed, controller
regressions, bad harness specialization, stale-binary runs, compile failures,
warmup outliers, and inconclusive screens. They also distinguish prepared but
unrun ideas from measured failures. Historical statements such as “default off”
describe the experiment at that time, not this release's defaults.

## Validation and reproducibility

The retained numerical changes passed exact finite-output gates. The latest
pair/trio Q8 and SwiGLU gates covered 50,000 draws per kernel; routed down covered
50,001 draws across expert-overlap cases. Gates include poisoned bounds, input
controls, and deterministic repeats. Earlier serial FFN validation compared
114 quality cases and 3,018 full-vocabulary logit vectors exactly.

Resident A/B trials restored cached prefixes at 8k, 62k, and 300k without
re-prefilling or reloading weights between arms. Quiet-machine checks preceded
timing; native profiling was kept separate from adoption timing. Forced-reject
checks at two/six rows matched serial continuations at all three depths.

The final 14-request held-out agent replay matched all text/phase hashes and
14,198 completion tokens per arm. The last incremental change improved answer
phase 49.273 to 50.040 t/s; whole decode improved 0.235%, with effectively
unchanged reasoning time. Those are incremental results, not cumulative gains
counted a second time. Small negative/neutral workload results are retained in
the [numeric evidence bundle](../bench/v41-20260916/README.md).

Build and run the focused, model-free production-path tests:

```sh
make -j8 all

make tests/test_ds41_controller tests/test_ds41_dspark_adaptive tests/test_ds41_markov_cache
./tests/test_ds41_controller
./tests/test_ds41_dspark_adaptive

```

Do not run another full model instance alongside a serving instance just to
repeat these checks. The existing [reproduction guide](REPRODUCE-V41.md) covers
resident cached-prefix fixtures and A/B APIs. Private agent request bodies and
conversation output are not redistributed; published summaries retain counts,
phase times, selection records, hashes, and failures. CUDA/distributed behavior
has not been newly certified by these Metal-only tests.
